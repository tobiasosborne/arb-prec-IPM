# golden/ — arbsdp golden-master test set

Generated by bead arb-prec-IPM-b09 using `wolframscript` (Mathematica).
All optimal values are certified by independent symbolic computation (see `gen/verify.wl`).

---

## Directory schema

Each problem lives in `golden/<name>/`:

```
golden/
  <name>/
    <name>.dat-s       -- problem in SDPA sparse format (parseable by SdpaSparse.ts)
    provenance.json    -- metadata + certified optimal value
  gen/
    generate.wl        -- Wolfram Language generator script (run once to regenerate)
    verify.wl          -- independent verification script
  verify.sh            -- shell wrapper: runs verify.wl via wolframscript
  README.md            -- this file
```

### provenance.json schema

```json
{
  "name":                 "<name>",
  "source":               "wolframscript",
  "description":          "<human-readable description>",
  "m":                    <integer, number of constraints>,
  "block_sizes":          [<integer, ...>],
  "maximize":             true,
  "optimal_value":        "<decimal string, >= 65 significant digits>",
  "optimal_value_digits": <integer, number of certified significant digits>,
  "reference_method":     "<derivation method>",
  "generated_by":         "arbsdp golden-master generator b09 / wolframscript 1.13.0"
}
```

`optimal_value` is ALWAYS a plain decimal string (no `e` notation, no spaces).
`block_sizes`: positive integer = PSD block of that size; negative integer = diagonal (LP) block.
`maximize: true` means the problem is stated as a maximization (SDPA convention).

### provenance.json schema v2 (runner fields)

v2 adds runner-facing fields consumed by the adaptive-solve regression gate. All
are OPTIONAL on read: a file without them falls back to the listed DEFAULT, so v1
files keep parsing. Calibrate the numbers from measured solver behavior
(`bench/brittle_probe.c`), never guess.

| Field | Type | Default when absent | Meaning |
|-------|------|---------------------|---------|
| `expected_status` | string | `"optimal"` | Required terminal status (`optimal`, `primal_infeasible`, `dual_infeasible`). |
| `target_digits` | int | `15` | Digits the runner REQUESTS and VERIFIES. Must be reachable within `prec_cap`; set at or just below the digits the adaptive solver actually achieves, so the correctness assertion PASSES. |
| `prec_cap` | int | `8192` | `prec_max` bits for the adaptive solve; a power of 2, set to the final_prec the problem needed (rounded up). |
| `correctness_tol_digits` | int | `0` | Slack on `target_digits` the correctness check tolerates (0 = exact reach required). |
| `expected_max_bits_per_digit` | int | `8` | GOAL ceiling on final_prec/achieved_digits (b30 target ~3-6). The current solver is far above 8 on every problem — that overrun is the `efficiency` known_gap, not a surprise. |
| `expected_max_iters` | int | `100` | Ceiling on adaptive iterations. |
| `known_gaps` | array | `[]` | Expected-fail markers; each `{kind, bead, reason}` with a CONCRETE measured reason. |

`known_gaps[].kind` vocabulary:
- `status` — the solver returns a different terminal status than `expected_status`.
- `correctness` — `target_digits` (within `correctness_tol_digits`) is NOT reached within `prec_cap`.
- `efficiency` — the bits/digit or iteration budget (`expected_max_bits_per_digit`, `expected_max_iters`) is exceeded.

xfail semantics: a `known_gap` of a given kind makes the gate TOLERATE that
failure class for this problem (expected-fail, reported but not fatal); but the
gate FAILS if that case unexpectedly PASSES, forcing removal of the now-stale
marker so the bar ratchets up.

### .dat-s format (SDPA sparse)

Parsed by `SdpaSparse.ts` (packages/solver-ipm/src/format/SdpaSparse.ts):
- Lines starting with `*` or `"` are comments.
- Line 1: `m` (number of constraints).
- Line 2: `nblocks`.
- Line 3: block sizes, space-separated.
- Line 4: `b` vector (right-hand sides), space-separated.
- Remaining lines: `i block k l v`
  - `i=0` → C (objective); `i=1..m` → A_i (constraint matrix i).
  - `block`: 1-indexed block number.
  - `k`, `l`: 1-indexed row/col, with `k <= l` (upper-triangle only).
  - `v`: value. For off-diagonal entries (`k < l`), the entry represents
    both `A_{kl}` and `A_{lk}` (full symmetric matrix), so
    `<A, X> += v * X_{kl} + v * X_{lk} = 2*v * X_{kl}`.
  - No `=` signs in data lines (the parser strips from `=` onwards as a comment).

All numeric values in the generated files are written as 65-digit plain decimals.

## Problems

| Name | Size | m | Optimal value | Type | Notes |
|------|------|---|---------------|------|-------|
| trivial_2x2 | 2x2 PSD | 1 | 1.0 | integer | BOUNDARY: X*=diag(1,0) singular |
| max_eigenvalue_2x2 | 2x2 PSD | 1 | 3.0 | integer | BOUNDARY: rank-1 X* |
| sdp_sqrt2 | 2x2 PSD | 2 | sqrt(2) = 1.4142... | irrational | BOUNDARY: rank-1 X* |
| lp_diagonal_block | diag block -5 | 3 | 7.0 | integer | LP as diagonal block |
| ill_conditioned_3x3 | 3x3 PSD | 3 | 1+10^-6 | rational | mildly ill-conditioned Schur |
| mixed_blocks | 2x2 PSD + scalar | 2 | 1+sqrt(2)/2 = 1.7071... | irrational | mixed PSD+LP blocks |
| max_eig_tridiag_3x3 | 3x3 PSD | 1 | 2+sqrt(3) = 3.7320... | irrational | BOUNDARY: rank-1 X* |

### Detailed descriptions

**trivial_2x2** — Minimal boundary case: `max x_11 s.t. x_11=1, X 2x2 PSD`.
The optimal X*=diag(1,0) is rank-deficient (singular). Tests CLAUDE.md invariant 1
(certify from dual side; verified Cholesky of X* will fail).

**max_eigenvalue_2x2** — `max <A,X> s.t. tr(X)=1, X 2x2 PSD` where A=[[2,1],[1,2]].
Variational formula: opt = lambda_max(A) = 3. X* = [[1/2,1/2],[1/2,1/2]] is rank-1 singular.

**sdp_sqrt2** — `max x_12 s.t. x_11=1, x_22=2, X 2x2 PSD`.
PSD requires x_12^2 <= 2; opt = sqrt(2). X* = [[1,sqrt(2)],[sqrt(2),2]] is rank-1.
Tests high-precision irrational value and boundary optimum simultaneously.

**lp_diagonal_block** — `max x1+2*x2 s.t. x1+x2<=4, x1<=3, x2<=3` with slacks.
Encoded as a single diagonal block (block_size=-5). Tests LP-as-diagonal-block code path.

**ill_conditioned_3x3** — `max x_11+1e-6*x_22 s.t. x_11=1, x_22=1, 2*x_12=0, X 3x3 PSD`.
The small coefficient epsilon=1e-6 in C creates mild ill-conditioning in the Schur complement
matrix during the IPM solve. Tests precision handling for nearly-flat objectives.

**mixed_blocks** — `max (X_1)_11 + x_2 s.t. tr(X_1)=1, x_2+x_12=1/2` with
block_sizes=[2,-1]. Tests the mixed-block code path with one PSD and one LP block.

**max_eig_tridiag_3x3** — `max <A,X> s.t. tr(X)=1, X 3x3 PSD` where A=[[3,1,0],[1,2,1],[0,1,1]].
opt = lambda_max(A) = 2+sqrt(3). Tests a 3x3 problem with irrational optimum and rank-1
boundary X*.

## How beads b10 and b23 consume this set

**b10 (solver integration test):** For each problem, run `arbsdp solve <name>.dat-s --prec P`
and check that the returned `[lb, ub]` bracket CONTAINS `optimal_value` (read from
`provenance.json`). This is the "bracket" relation from PRD §6; it is falsifiable (any
failure is a P0 bug per CLAUDE.md rule 2). The check is:
```
lb <= optimal_value <= ub   (all parsed as high-precision numbers)
```

**b23 (beat/bracket regression suite):** For each problem, also check the "beat" relation:
that the solver returns more correct digits than a float64 solver would. Concretely, compare
`|midpoint([lb,ub]) - optimal_value|` against the float64 solver's error on the same problem.

## Regenerating

```bash
cd /path/to/arb-prec-IPM
wolframscript -file golden/gen/generate.wl
```

The generator is deterministic and idempotent (overwrites existing files).

## Verifying

```bash
bash golden/verify.sh
```

Expected output: `ALL PASS: stored values match independent computations to stated digits.`
